# RCA — "Live app missing newest features after publish"

## Problem statement
User reports production (`https://employee-portal-366.emergent.host`) does not show two newly built features that work in preview:
1. Admin > Attendance header switch "Show attendance to employees" (`data-testid=employee-sheet-toggle`, `src/components/SheetVisibilityToggle.jsx`, backend GET/PUT `/api/admin/settings/employee-sheet`)
2. Employee "My attendance" month calendar (`src/components/MyMonthSheet.jsx`, backend GET `/api/attendance/my-sheet`)

## Verdict: NOT a deployment problem — production IS serving the latest build with these features.

## Evidence

### 1. Latest deployment finished successfully
- `describe_deployment_state`: active_run_id = `c1e1bf9a-1e5d-4543-8924-deb13db76d19`, type=`redeploy`, status=`success`, completed_at=`2026-10-18T02:42:05Z`.
- Serving image `...customers-app@sha256:c09ebd33fe04...` (newer than the initial run's `sha256:0587b195...`).
- frontend_type = `cloudflare` (static assets served from R2 via Cloudflare worker; backend on k8s).

### 2. Backend routes EXIST on production (not a stale 404 build)
- `GET /api/admin/settings/employee-sheet` → **401** `{"detail":"Not authenticated"}` (route exists, gated by auth).
- `GET /api/attendance/my-sheet` → **401** `{"detail":"Not authenticated"}` (route exists).
- 401, not 404 → the production backend is running the new build.

### 3. Deployed source (run c1e1bf9a) contains the new files/routes
Verified in eph sandbox at `/app/scratch`:
- `frontend/src/components/SheetVisibilityToggle.jsx` present; contains `data-testid="employee-sheet-toggle"`.
- `frontend/src/components/MyMonthSheet.jsx` present.
- `backend/server.py:697` `@api.get("/admin/settings/employee-sheet")`, `:702` `@api.put(...)`, `:708` `@api.get("/attendance/my-sheet")`.

### 4. The LIVE frontend bundle already contains the features
- Live `/` references `/static/js/main.80d01a41.js`.
- Fetched that live bundle (584,784 bytes) with a browser User-Agent and grepped:
  - `employee-sheet-toggle` → **present**
  - `my-sheet` → **present**
  - `Show attendance to employees` → **present**
  - (`MyMonthSheet` as a literal → absent, expected: component names are minified away; the testid/label string literals are the reliable signal.)

### 5. No custom domain involved
- `list_domains` → none. User is on the default `.emergent.host` URL, so no separate custom-domain CDN cache.

## Root cause
Production already serves the new build on both backend (routes return 401, not 404) and frontend (live bundle `main.80d01a41.js` contains the toggle testid, the `my-sheet` reference, and the "Show attendance to employees" label). The reason the user does not see the features is a **stale client-side / browser cache serving an older index.html + JS bundle**, not a failed or incomplete deployment.

## Suggested fix
- **User (test_and_verify):** Hard refresh (Ctrl/Cmd+Shift+R) or open the live URL in an incognito/private window to drop the cached bundle. Then log in and open `/admin/attendance` (toggle) and the employee "My attendance" page. The admin toggle and my-sheet calendar are auth-gated (401 when not logged in), so they only render for an authenticated session with the right role.
- No redeploy, secret change, or code change is required — production is up to date.
